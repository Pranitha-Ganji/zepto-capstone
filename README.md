# Zepto Data & AI Platform

This repository contains the capstone project for the Zepto Data & AI Platform, consisting of three main modules:

* **Data Pipeline (`/data_pipeline`)**: Scrapes book data, cleans it, and stores it in a SQLite database along with SQL analytics.
* **Analytics Pipeline (`/analytics`)**: End-to-end data profiling, visualization, and predictive modeling on the Titanic dataset.
* **Support Assistant (`/support_assistant`)**: A locally-run RAG (Retrieval-Augmented Generation) application built with LangGraph and FastAPI, answering questions based on Zepto's policies.

---

## 🏗️ RAG Pipeline Architecture

The support assistant processes customer queries through a four-stage RAG pipeline:
1. **Ingestion Stage**
   * **Component / File:** `support_assistant/ingest.py`
   * **Role:** Loads raw policy documentation, cleans the text, and splits it into discrete chunks for vector indexing.

2. **Embedding Stage**
   * **Component / File:** `support_assistant/vector_store.py` (or `embeddings.py`)
   * **Role:** Converts text chunks into vector embeddings and indexes them inside the local vector store.

3. **Retrieval Stage**
   * **Component / File:** `support_assistant/retriever.py`
   * **Role:** Receives incoming support queries, converts them to vectors, and retrieves the top-$k$ most relevant policy context chunks.

4. **Generation Stage**
   * **Component / File:** `support_assistant/generator.py` (or LangGraph node)
   * **Role:** Constructs a prompt combining system rules, retrieved context chunks, and the user query, then passes it to the generation backend.
### MOCK_LLM Branching Logic

The **Generation stage** conditionally branches based on the state of the `MOCK_LLM` environment variable or flag:

* **When `MOCK_LLM=True` (Mock Mode):**
  * Bypasses external API calls to enable fast, offline testing.
  * Generates a deterministic canned response directly grounded in the retrieved context chunks without requiring live API keys.

* **When `MOCK_LLM=False` (Live LLM Mode):**
  * Connects to the live API client (e.g., OpenAI, Gemini, or local Ollama instance).
  * Sends the complete context-enriched prompt over the network and returns dynamic, real-time responses generated by the model.
